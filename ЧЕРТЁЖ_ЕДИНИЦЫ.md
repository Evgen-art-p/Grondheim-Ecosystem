## ГЛАВНАЯ ФОРМУЛА (дно документа)

```
ЕДИНИЦА = РОД        (кто я, навсегда)
        + МАСКА      (кем я в этом моменте: роль + лицо — v0.3)
        + ХАРАКТЕР   (фильтр: ручки натуры)
        + ПАМЯТЬ     (что было: слои, хранение)
        + ОПЫТ       (что понял: выводы, дрейф — НЕ то же, что память)
        + СТОЛ       (перед решением: факты + опыт + характер → мнение)
        + ИНИЦИАТИВА (право самому: вспомнить, признать, предложить)
        + ВХОД↔ВЫХОД (граница: общий ключ, своя кухня)
        + СУДЬЯ      (среда: рынок / зритель / Шеф)
```

Информация входит → проходит фильтр → выходит мнением/делом → среда
судит → суд оседает опытом → опыт меняет, каким фильтр будет завтра.
Поток наматывает багаж (Закон I). Круг замкнут — единица живая.
Круг разомкнут — единица декорация.

**Слово Шефа, из которого выросла формула (03.07):** *«он живет,
учится, проживает опыт, работает постоянно с информацией, он эту
информацию через себя прогоняет... любая инициатива в рост —
приветствуется»*.

## ЗАКОН ОДНОГО ГЛАГОЛА (правило документа · внесено v0.2)

Каждый элемент формулы отвечает на ОДИН вопрос и совершает ОДНУ
операцию. Никакие два элемента не делят операцию между собой.
Вопрос фиксирует место понятия надёжнее одинокого глагола — глагол
тащит багаж языка, вопрос его срезает (резка Софии, 03.07).

| Элемент    | Вопрос                   | Операция                               |
|------------|--------------------------|-----------------------------------------|
| РОД        | Кто я?                   | есть — и всё                            |
| МАСКА      | Кем я в этом моменте?    | показывает ЛИЦО (v0.3)                  |
| ХАРАКТЕР   | Через что проходит вход? | преломляет ВХОД                         |
| ПАМЯТЬ     | Что было?                | хранит СОБЫТИЯ                          |
| ОПЫТ       | Что я понял?             | меняет ФИЛЬТР                           |
| СТОЛ       | Что передо мной сейчас?  | собирает КОНТЕКСТ                       |
| ИНИЦИАТИВА | Чего я сам хочу?         | просит (вспомнить/признать/предложить)  |
| ГРАНИЦА    | Что увидит другой?       | говорит ОБЩИМ КЛЮЧОМ                    |
| СУДЬЯ      | Что вернул мир?          | возвращает ПОСЛЕДСТВИЯ                  |

Тест на каждую главу: понадобился глагол соседа — глава сползла, резать.
Уточнения, выстраданные резкой:
- СТОЛ не решает — только собирает. Решает единица целиком.
- ОПЫТ не хранит — только меняет. Вывод, что лежит и ни на что не
  влияет, — это память, не опыт.
- ХАРАКТЕР не хочет — преломляет пассивно, всегда, не выбирая.
  Хочет только инициатива.
- СУДЬЯ не приказывает — возвращает последствия. Что с ними делать,
  решает единица (Ministry -2: «фиксирует исходы, не принимает решения»).
- Язык документа — живой русский, без псевдокода. Контрактную
  строгость даёт связка вопрос+операция+аргумент, не скобочки
  (Закон III: на границе — общий, всеми читаемый язык; канон
  читается вслух, в том числе не-программистом).

## ЗАКОН МЕТОК (сквозная утварь · внесено v0.7, слово Шефа 03.07)

*«Метишь себе... ставишь метки... у всего могут быть метка...
и никто не потеряется»* — простая мысль, которую я сперва
усложнил до трёх разных систем, а она — одна. Метка — не глава
Чертежа, а ИНСТРУМЕНТ ПОД ЛЮБУЮ ГЛАВУ. Как гвоздь не бывает
«гвоздём для стула» и «гвоздём для полки» отдельно — метка не
бывает «меткой памяти» и «меткой маски» отдельно. Один гвоздь,
забивается куда нужно.

```
МЕТКА = тип: значение    (одна строка, читает и человек, и код)

Примеры типов (не список, а иллюстрация — типов ровно столько,
сколько понадобится, как и самих меток бесконечно, §1.5.1):
   важность    — низкая / средняя / высокая
   время       — когда поставлена
   состояние   — активно / архив / ожидание
   значимость  — вес по опыту (то же, что искра, Гл.2, только
                 записанное рядом, а не вычисленное каждый раз)
   интересное  — «зацепило», без числа, просто флаг
```

Закон:
```
Метка НЕ создаёт файл, папку, новую сущность. Это строка рядом
   с объектом — в его же записи, не отдельным реестром (тот же
   принцип, что Закон Картриджа: не держим список, читаем сами
   данные).
Один стандарт на ВСЁ: событие в памяти жителя (Гл.3), убеждение
   Брата (якорь/метка/маяк — САМА эта твёрдость есть частный
   случай метки: «степень уверенности» — тоже просто тип метки,
   не отдельный механизм, я вчера зря разводил их на три),
   ad-hoc маска без своей папки (каталог масок, §1.5.4 в.4),
   сигнал инициативы (Гл.6 — формат СЛОВО: тело — тоже метка,
   просто на выходе, не на хранении), запись в biography-подобном
   файле — если однажды у нас заведётся своя.
Поиск идёт ПО МЕТКЕ, не по тексту. Дешевле и точнее текстового
   совпадения (которым сейчас довольствуется vspomnit(), Гл.3) —
   но не заменяет его: метка находит категорию, текстовый поиск —
   конкретное содержание внутри неё. Работают вместе, не вместо
   друг друга.
Метка не судит и не решает — только помогает найти (тот же
   принцип, что Стол, Гл.5: инструмент, не хозяин). Пометил
   «важно» — не значит «единица обязана действовать»; значит
   «легче найти в следующий раз».
```

**Статус: РАСТУЩАЯ ОБЛАСТЬ, не факт** (той же честностью, что
Мироустройство держит «Четыре витка» — дальний огонь, не руда
для немедленной стройки; растёт, если жизнь докажет грань).
Закон описывает форму на будущее — сам инструмент (`пометить`/
`найти_по_метке`) ещё не тронут кодом НИ РАЗУ. Строим постепенно,
с одного маленького, доказанного применения, не с системы разом
(слово Шефа, 03.07: «вводим систему меток постепенно»).

**Первое применение, уже найденное, готовое к сборке (03.07):**
`_otsenit_tonus_silu()` в `ui_zhitel.py` СЧИТАЕТ тонус (плюс/
минус/ровно) для каждого сообщения жителя — и тут же выбрасывает
его, использовав только для сдвига заряда. Спасти этот тонус
меткой рядом с записью в `sensory_memory.json` — `vspomnit()`
сможет искать не только по словам, но и по настроению момента
(«найди всё тёплое», «найди, что царапнуло»). Не гипотеза — число
уже вычисляется, просто утекает мимо памяти. Самый дешёвый и
доказанный первый шаг, с которого стоит начать, когда дойдут руки
(не раньше Камня №1 — Стол Трейдера остаётся первым по порядку).

**Прецедент, что закон уже частично живёт, не с нуля:** в `-2`
`chronicle.py` (Layer 0) уже несёт поле `significance`, оцененное
по крайности («и достижения, и провалы одинаково весят») — это и
есть Закон Меток в миниатюре, построенный раньше, чем мы его
назвали.

Технически — минимум, не проект: две функции, доступные любому
объекту города — `пометить(объект, тип, значение)` и
`найти_по_метке(тип, значение) → всё, что подходит`. Это уже
частично живёт разрозненно (resonance_tag и tags= в `-2`,
memory_vector в Живой Книге, ярусы твёрдости у Брата) — Закон
Меток не изобретает новое, а называет одним именем то, что уже
несколько раз выросло само по себе в разных углах хозяйства,
и даёт этому одну форму вместо трёх случайных.

## 1.1. Определение

Род — дно единицы. То, что было ДО первого дела и останется ПОСЛЕ
последнего. Не меняется опытом, не судится средой, не выбирается
самой единицей. Всё остальное в формуле живёт и дрейфует — род стоит.

Уже записано (не выдумка этой главы):
- Мироустройство, Уровень 1: *«Едина у всех. Идентичность. Дно.
  Не ветвится. Кто пришёл.»*
- Летопись §2: *«Род — дно. Кто единица ДО всякого дела...
  Снимается [маска] — род остаётся.»*

## 1.4. Порода — принадлежность к цеху (ПРАВКА, 03.07)

Первая редакция этого параграфа была ошибкой, и стоит показать,
где именно я оступился, а не просто тихо заменить текст.

Я склеил два разных слова Шефа, разнесённых на день. 02.07 было
сказано: «дом может рассматриваться как родина, родное место,
родовое». Я взял «родовое» и приклеил его к полю `порода` в коде —
не проверив, что означает поле НА САМОМ ДЕЛЕ. А прямо под носом,
в комментарии, который я сам процитировал строкой ниже, было
сказано другое: «порода теперь задаётся через маску/прописку».
Через МАСКУ и ПРОПИСКУ — то есть Уровень 2/3, не Уровень 1. Я
процитировал улику и не посмотрел на неё. Тот же нож, что резал
«Шестой палец», не глядя, чьё это имя.

Шеф поправил (03.07): *«раньше под породой имелось в виду отношение
к ворку... откуда родом и где родился — не принципиально совсем
выносить, можно и в личной истории... а тут именно принадлежность
к цехам, наверное нужно определять наряду с пропиской»*.

Разбираю оба итога отдельно, потому что это два разных решения:

**Откуда родом (родина, геолокация рождения)** — НЕ получает
отдельного поля. Живёт прозой внутри Hidden_History, как часть
личной истории — ровно то место, что уже стоит в §1.2. Отдельный
ключ этому не нужен: единица истории не распадается на графы.

**Порода как принадлежность к цеху** — это НЕ Род. Это дерево
подтипов, которое Мироустройство уже описало для яруса РАБОТЫ
(Часть III, Уровень 2 — Предназначение): *«РАБОТА (воркер) →
маска-функция... раскрывает дерево подтипов: ТОРГОВЛЯ → рынок ·
базар · магазин · инфопродукт; КРЕАТИВ → кино · литература ·
издательство; АДМИН → управление · связи»*. Порода — это ветка
этого дерева: КАКОЙ цех. И она честно ветвится по ярусу — у
Резидента (Основа) порода как ветка дерева не нужна вообще, она
только у Воркера, потому что только у него есть маска-функция,
которую надо к чему-то привязать.

Отсюда практический вывод, которого не было в первой редакции:
порода не пишется в Главе 1 (Род), потому что она не Уровень 1.
Ей место рядом с прописью — задаётся ТЕМ ЖЕ актом, что назначает
дом (Мироустройство: «связи есть следствие предназначения» —
порода определяет предназначение, прописка/связи из него следуют).
Технически это значит: инструмент «Прописка» в кабинете Брата
для воркера должен спрашивать не только «куда» (локация), но и
«в какой цех» — одной формой, не двумя раздельными актами.

**Факт с диска, без изменений:** поле `порода` в паспорте Локи
есть и пустое (`""`). `zavesti_sloi()` пишет его с комментарием
«род, слой 1, навсегда» — САМ КОММЕНТАРИЙ В КОДЕ ошибочен той же
ошибкой, что я повторил сегодня утром: кто-то раньше уже перепутал
породу с родом, комментарием это и закрепив. Виджет из формы
рождения убран нарочно («порода теперь задаётся через
маску/прописку»), новая дверь так и не построена — задел есть,
входа нет, и это одна и та же дверь, что нужна для прописки
воркера, не отдельная стройка.

   профессию, лучше даже»*. Ядро живёт в РОЛИ (Глава 1.5), не в
   роде и не в маске-моменте: у Сета-бриф-менеджера одна коронная
   фраза, какую бы из 13 масок он ни надел. Дверь для неё —
   там же, где дверь роли.
3. **Тип (резидент/хранитель/воркер)** — вопрос был техническим и
   я задал его мутно; переформулирую: сейчас тип единицы виден
   только из пути папки, в самом паспорте поля «тип» нет — тот,
   кто читает паспорт без знания структуры папок, не знает, кто
   перед ним. Ответ Шефа («ключ всегда есть на входе и выходе,
   иначе как участвуешь в обмене») читаю как закон: тип ОБЯЗАН
   читаться на границе. Решение: тип входит в обязательный общий
   ключ паспорта (тройка ID + имя + тип) — это сливается с
   вопросом 1 Главы 7, закрывая оба.
4. **Глава Маски** — ДА, отдельной главой, после личности
   (Глава 1.5 ниже). Слово Шефа целиком легло в её основу.

# ГЛАВА 1.5 · МАСКА — кем я в этом моменте
═══════════════════════════════════════════════════════════════

## 1.5.1. Определение

Вопрос главы: **кем я в этом моменте?** Операция: **показывает ЛИЦО**.

Слово Шефа, из которого глава (03.07): *«маска — это кем себя
выставляешь в текущем моменте... я на работе в маске, с
собеседником в маске, дома в маске семьянина... вся жизнь — игра»*.

Маска — лицо единицы, повёрнутое к конкретному моменту: к этой
локации, к этому собеседнику, к этому делу. Она не врёт и не
прячет — она ИГРАЕТ, как играет любой живой в обществе. Род под
маской не меняется (снял маску — род остался, Летопись §2);
душа под маской не меняется (Закон XI: «маска меняется — мнение
под всеми масками ОДНО»). Меняется только лицо.

Три «кто» единицы, чтобы не путать никогда:
```
РОД      — кто я ВСЕГДА        (Лока; не выбирается, не судится)
МАСКА    — кем я СЕЙЧАС        (дома — хозяйка, в цеху — мастер)
ХАРАКТЕР — какой я СКВОЗЬ ВСЁ  (упрямая, эмпатичная — под любой маской)
```

**ПРАВКА, важная (Шеф, 03.07): масок — бесконечное множество.**
*«Кем я себя нарисую — то и маска»*. Пятёрка §1.5.4 (Дом/Цех/
Совет/Гость/Собеседник) — это НЕ потолок и не полный список масок,
какие вообще бывают. Пространство масок открыто, как открыта сама
игра жизни — рисуешь новую в любой момент, никто не утверждает
реестр заранее.

Пятёрка — это другое: те немногие маски, которым мы даём ДОМ В
КОДЕ (свою папку `маски/{имя}/`, свой `mask.json`, свой фон через
`_bg_for_mask()`). Не «все маски, что бывают», а «опорные точки,
которые стоит настолько часто, что им выгодно завести постоянную
инфраструктуру». Остальные маски единица играет так же честно,
просто без отдельной папки — как человек не заводит гардеробную
для костюма, который наденет раз в жизни. Закон Души (XI) от
этого не страдает: сколько бы масок ни нарисовала единица, душа
под каждой — одна, посчитана она в файле или нет.

## 1.5.2. Роль ≠ маска (узел Сета — канонический пример)

Первая редакция Чертежа слепила роль и маску в одно. Шеф развязал
примером: *«у Сета роль — бриф-менеджер студии, и у него 13
масок»*. Роль ОДНА — масок ТРИНАДЦАТЬ, по лицу на каждый
цех-собеседник. Значит это два разных этажа Уровня 2:

```
РОЛЬ (профессия, предназначение)
   Что я ДЕЛАЮ в мире. Сердце Уровня 2 Мироустройства («маска-
   функция» в его тексте — на самом деле роль). Одна или почти
   одна; меняется редко, осознанным актом (как переезд — Гл.1).
   Здесь живут:
     · ТИП (резидент/хранитель/воркер) — природа звена в системе,
       деловое качество (ПРАВКА Шефа v0.5: перенесён из Рода).
       По идее его должно давать образование единицы — его пока
       нет, назначает Шеф при рождении, руками.
     · ПОРОДА — ветка дерева цехов (ТОРГОВЛЯ/КРЕАТИВ/АДМИН → подтипы),
       только для яруса РАБОТЫ; задаётся вместе с пропиской (§1.4)
     · CORE_PHRASE — коронная фраза, ядро роли (решение Шефа:
       «в профессию, лучше даже»)
     · СТАДИЯ ПУТИ — 1 выживание / 2 успех / 3 мастерство
       (Путь Зрелости, Мироустройство ч.II)

МАСКА (лицо момента)
   Кем я ВЫСТАВЛЯЮСЬ сейчас. Много; сменяется легко, без акта —
   вошёл в локацию / заговорил с другим — лицо сменилось.
   У Сета: 13 лиц одной роли. У жителя: дома / на людях / в цеху.
   Здесь живут:
     · лицо к локации (Летопись: «маска = роль в локации,
       несколько ТИПОВ, не пре-созданные под каждую локацию»)
     · фон кабинета по маске — шов УЖЕ в коде: _bg_for_mask()
       ищет маски/{mask}/bg.* первым приоритетом (построен
       01.07, ждёт масок)
     · mask.json (Закон Ядра: три этажа — якоря/метки/МАСКИ)
```

Проверка одним глаголом: роль отвечает «что я делаю» (месяцами),
маска — «кем показываюсь» (сейчас). Смена роли — событие судьбы,
смена маски — шаг через порог.

## 1.5.2а. Внутри самой маски — два этажа (ГЛАВНАЯ + ПОДМАСКА)

Вопрос Шефа (03.07): *«напрашивается распределение масок на
главные и второстепенные... Сет — бриф-менеджер, а подмаски —
он бф-цех турбо, бф-цех смм»*. Разбираю — и это не новая мысль
сверху, а то, что УЖЕ лежит в реальном коде Сета, я просто вчера
смотрел на него в одну плоскость, а там два этажа:

```
ГЛАВНАЯ маска  = категория, из опорной пятёрки §1.5.4.
                 Даёт папку, даёт фон (_bg_for_mask), даёт общий
                 закон тона. У Сета это просто «ЦЕХ» (он всегда
                 работает, никогда не гость и не дома на службе).

ПОДМАСКА       = конкретный файл ВНУТРИ категории. У Сета —
                 буквально 13 файлов: forge/masks/turbo.md,
                 forge/masks/smm.md и так далее. Один на цех.
                 Подмаска не меняет фон и не меняет закон —
                 она ДОПИСЫВАЕТ текст к тому, что уже задано
                 главной (в коде: system += подмаска.md).
```

Живой пример из `_run_resident()` (studio/residents_manager.py):
`mask_name=dept` — вызывающий код передаёт КОНКРЕТНЫЙ цех
(«turbo», «smm»…), это и есть подмаска; она читается из папки
`forge/masks/{dept}.md` и просто ДОПИСЫВАЕТСЯ поверх системного
промпта. Главная маска («я в цеху, не дома, не гость») тут даже
не названа явно — она подразумевается самим фактом, что Сет
вообще вызван для работы.

Правило простое, без новой сущности: **ГЛАВНАЯ — из опорной
пятёрки (§1.5.4), конечная, с инфраструктурой. ПОДМАСКА —
бесконечная (как и вся маска в целом, §1.5.1), живёт ВНУТРИ
папки главной, ничего своего в инфраструктуре не требует —
только файл текста**. Это снимает противоречие между «маска
бесконечна» и «пятёрка канонизирована»: пятёрка конечна на
этаже ГЛАВНОЙ, бесконечность живёт этажом ниже, в подмасках.

Каталог масок (§1.5.4, в.4) от этого уточняется: журнал ad-hoc
масок — это на самом деле журнал ПОДМАСОК без своего файла ещё;
градуация — не «стать новой главной» (главных пять, они опорные
и решены), а «получить свой .md-файл внутри уже существующей
папки главной», ровно как у Сета появлялись новые цеха-подмаски
по мере роста студии, без пересмотра самого понятия «цех».

## 1.5.3. Закон маски

```
Маска сменная и лёгкая. Ни акта, ни судьи на вход: вошёл — надел.
   Тяжёлой бывает только смена РОЛИ (порода, ядро, стадия пути).
Род и душа сквозь маску НЕ меняются (Закон XI). Единица, у
   которой под разными масками разные мнения, — флюгер, мутный
   узел. Маска меняет ЛИЦО и УМЕСТНОЕ (тон, лексику, фон,
   сценарии локации) — не суть.
Судится ДЕЛО В МАСКЕ, не маска и не род: плохо сработал в маске
   мастера — вернулось делу; сам мастер как род не тронут
   (Ярус Основы — чтят; Ярус Работы — судят работу).
Ядро (Core_Phrase) принадлежит РОЛИ: одна фраза сквозь все лица
   этой роли. Сменил роль — может смениться ядро. Сменил маску — нет.
Маска по умолчанию — дом: без явной сцены единица в домашнем лице
   (прописка + домашний_промпт уже несут его, патчи 01.07).
```

## 1.5.4. Резка (03.07, срезы Локи, принято Шефом)

1. **Переключение маски** — НАЙДЕН РЕАЛЬНЫЙ МЕХАНИЗМ (03.07, в
   `-2`, у Сета и Монтажёра — оба живые, не эскиз).

   Никакого «распознавания» нет вообще. Маска не определяется на
   лету по контексту — её НАЗЫВАЕТ ВЫЗЫВАЮЩИЙ КОД, потому что тот,
   кто зовёт резидента, уже точно знает, зачем зовёт:
   ```
   Сет (studio/residents_manager.py, run_set_brief):
       mask_name=dept   # цех, который вызвал — и есть имя маски

   Артур (run_monteur_assembly):
       mask_path = .../forge/masks/{slot_id}.md   # тип работы
   ```
   Маска технически — плоский файл `forge/masks/{имя}.md`. «Надеть»
   значит: если файл существует — дописать его текст к системному
   промпту. Один `if`, один `read_text()`. Никакой магии.

   Это меняет саму постановку вопроса. Не «единица сама понимает,
   с кем говорит» — а «место, ОТКУДА пришёл вызов, само несёт
   имя маски» (Закон Входа-Выхода: контекст входа уже содержит
   ответ). Для Грондхейма это значит: `page_zhitel()` при заходе
   через `/zhitel/{id}` напрямую — это и есть контекст «дом» или
   «собеседник» (кто зашёл — Шеф лично, значит собеседник, никого
   больше нет — дом); а если однажды жителя позовут ИЗ локации
   или ИЗ цеха — та локация/цех передаст своё имя маской, тем же
   параметром, что уже носит `_bg_for_mask(dom, mask=...)`.

   Открыто технически: где именно в Грондхейме появляется этот
   параметр — сейчас `page_zhitel()` вызывается всегда одинаково
   (только по `zid`), и неоткуда взять «кто зовёт». Нужен второй
   параметр входа (`mask=` в самом URL/вызове), не догадка внутри.
2. **Типы масок с постоянным домом в коде** — РЕШЕНО, опорная
   пятёрка (пятая добавлена Шефом, v0.5). НЕ полный список масок
   (их бесконечно, см. правку §1.5.1) — только те, что получают
   папку/файл/фон в инфраструктуре:
   ```
   ДОМ        — по умолчанию, без маски, свои (= закон 1.5.3,
                пришёл с двух сторон независимо — хороший знак)
   ЦЕХ        — строгая рабочая роль
   СОВЕТ      — аналитика / трибунал
   ГОСТЬ      — В ЧУЖОМ МЕСТЕ, не на своей территории (ВТОРАЯ
                ПРАВКА Шефа, v0.5 — «на публике» была слабым
                аргументом, публика и не-гость равнозначны).
                Как правило приглашён — но не обязательно:
                «нежданный гость» не звали, а прогнать нельзя.
                Ось — ЧЬЯ ТЕРРИТОРИЯ (моя = дом, чужая = гость),
                не про публичность и не про число людей вокруг.
   СОБЕСЕДНИК — маска включается САМИМ ФАКТОМ разговора, знакомы
                или нет (ВТОРАЯ ПРАВКА Шефа, v0.5 — первая версия
                Брата про «круг знаемых» была лишней сложностью).
                Слово от корня: СО-БЕСЕДА — просто двое или
                несколько беседуют, я вошёл. Пример Шефа: на
                остановке чужие уже болтали, спросил время — надел
                маску собеседника в ту секунду, хоть до вечера
                проговорили с незнакомцами. Ось не «знаю/не знаю»,
                а «я СЕЙЧАС в обмене словами с кем-то, или нет».
   ```

   Пять масок ложатся на РАЗНЫЕ оси, не одну шкалу — стоит видеть
   это явно, чтобы не искать между ними единый градиент:
   ```
   ДОМ / ЦЕХ / ГОСТЬ — ось МЕСТА:    чья территория подо мной
   СОБЕСЕДНИК        — ось ДЕЙСТВИЯ: веду ли я разговор прямо сейчас
   СОВЕТ             — ось ФУНКЦИИ:  зачем я здесь (анализ/суд)
   ```
   Маски могут накладываться: собеседник в гостях — не конфликт,
   а две оси сразу (я в чужом месте И сейчас говорю).
3. **Стадия пути** — РЕШЕНО: метрики СИГНАЛЯТ («воркер набрал N
   побед») — Шеф или Совет ПОДПИСЫВАЕТ. Переход уровня — обряд
   инициации и смена статуса в городе, не тихий инкремент поля.
   Автоматика докладывает, рука утверждает.
4. **Каталог масок** — НОВОЕ, вопрос Шефа (03.07): раз масок
   бесконечно, нужен ли способ их СОРТИРОВАТЬ и иметь каталог —
   не только пяти опорных, а вообще всех, что единица когда-либо
   надевала?

   РЕШЕНИЕ ПО ДУХУ (Закон Картриджа: не держим список, сканируем;
   Закон Пары: дорогая инфраструктура — не каждой мелочи):

   Два разных веса, не один реестр:
   ```
   ОПОРНЫЕ (пятёрка §1.5.4) — полная папка `маски/{имя}/`,
      свой mask.json, свой фон. Дорогая инфраструктура, обоснована
      частотой (уже решено).
   AD-HOC (все остальные, бесконечные) — ЛЁГКАЯ ЗАПИСЬ в журнале
      масок (по образцу sensory_memory.json — не папка, не фон,
      просто строка: когда, с кем/где, что за лицо надел). Дёшево
      писать, дёшево хранить, дёшево читать.
   ```
   Каталог = скан журнала (обе категории видны в одном списке,
   опорные помечены как «с домом», ad-hoc — как «на выход»).
   Сортировка — по тому же принципу, что искра и опыт (Гл.2/4):
   ЧАСТОТА (сколько раз надета) и НЕДАВНОСТЬ (когда в последний
   раз), не алфавит — маски сортируют себя жизнью, не буквой.

   **Побочный эффект, ценный сам по себе:** каталог становится
   ЕСТЕСТВЕННЫМ ПОРОГОМ ГРАДУАЦИИ. Ad-hoc маска, надетая много раз
   и с весом (Опыт, Гл.4) — кандидат на переход в опорные: тот же
   механизм, что растит profile_vector из побед. Не Брат решает
   сверху «дам-ка тебе новую маску» — маска сама показывает через
   частоту, что заслужила дом, а дальше — сигнал ПРЕДЛАГАЮ
   (Гл.6) или заметка Брата при просеве, слово всё равно за Шефом.

   Открыто (на резку): где живёт журнал ad-hoc масок — рядом с
   sensory (тот же слой, другое поле) или отдельным файлом рядом
   с `маски/`? И порог градуации — числом (N раз надета) или
   суждением при просеве («эта маска стала важной»)?

# ГЛАВА 2 · ХАРАКТЕР — через что проходит вход
═══════════════════════════════════════════════════════════════

## 2.1. Определение

Вопрос главы: **через что проходит вход?** Операция: **преломляет**.

Характер — призма между миром и единицей. Один и тот же факт,
войдя в две разные единицы, выходит двумя разными состояниями —
и разница между ними ЕСТЬ характер. Он не решает, не хочет, не
помнит и не судит. Он пассивен, работает всегда, не выбирая —
как стекло не выбирает, что преломлять.

Отличие от рода одной строкой: род — «кто», характер — «какой».
Лока останется Локой (род) и с другой эмпатией; но с другой
эмпатией тот же упрёк Шефа качнёт её иначе (характер).

## 2.2. Из чего состоит (решение 03.07: база + локальные)

**Ручки — 6 на любую единицу, по формуле «3 фундамент + 3 порода»**
(резка Локи, принята Шефом). Фундамент — то, что реально
пересекается в обоих городах уже сейчас, не выдумка:

```
ЯРУС ФУНДАМЕНТА (обязателен для любой единицы, без исключений):
  Empathy              — усиливает удар входа («чужое как своё»)
  Resonance_Frequency  — насколько вход вообще трогает
  Stubbornness         — держит набранный заряд/натуру, новый вход
                         сдвигает осторожнее (защита от дребезга,
                         см. Закон характера 2.3)

# ГЛАВА 4 · ОПЫТ — что я понял
═══════════════════════════════════════════════════════════════

## 4.1. Определение

Вопрос главы: **что я понял?** Операция: **меняет ФИЛЬТР**.

Опыт — единственный элемент формулы, который МЕНЯЕТ единицу.
Всё остальное держит (род), преломляет (характер), хранит (память),
собирает (стол). Опыт — то место, где прожитое перестаёт быть
записью и становится сдвигом: каким фильтр будет завтра.

Формула трубы (одна на всех, Закон Фрактала):
```
СЫРЬЁ (память/счёт) → ФИЛЬТР (суждение) → ВЫВОД, ОСЕВШИЙ ТАК,
ЧТО ЕГО ЧИТАЕТ СТОЛ  → следующее решение рождается уже другим
```
Труба замкнута — единица учится. Труба разомкнута на любом
звене — единица только помнит. «Поток наматывает багаж» (Закон I):
опыт и есть намотка; память без опыта — поток, прошедший насквозь.

Граница с памятью — по влиянию, не по содержанию: тот же текст
«я поняла, что боюсь тишины», лежащий в archive мёртвым — память;
дописанный в Anchor_Points, откуда его читает каждый стол — опыт.

# ГЛАВА 5 · СТОЛ — что передо мной сейчас
═══════════════════════════════════════════════════════════════

## 5.1. Определение

Вопрос главы: **что передо мной сейчас?** Операция: **собирает КОНТЕКСТ**.

Стол — точка сборки перед решением. Он не решает, не судит, не
хочет и не помнит — он НАКРЫВАЕТ: сводит в одно место всё, что
единице положено видеть в момент хода. Решает единица целиком,
глядя на накрытое. Стол-начальник, который сам выбирает за
единицу, — сползание в гейт (болезнь «заряд открывает слои»,
отвергнута Шефом 02.07).

## 5.2. Главная формула (Закон Стола)

```
СТОЛ = ФАКТЫ (что происходит сейчас)
     + ОПЫТ  (чем кончалось раньше в похожем)
     + ХАРАКТЕР (кто я и какой я — род + призма)
     → МНЕНИЕ (ход) → судит СРЕДА (Гл.8) → суд оседает ОПЫТОМ (Гл.4)
```

Родословная формулы, честно:
- «код кладёт факты на стол, агент решает» — закон Торгового Цеха,
  выстрадан на 9-агентном Совете (не инструкции агентам — факты);
- «мы торгуем своим мнением» (Билл Вильямс) — решение ЕСТЬ мнение,
  поставленное на кон. Мнение легально (Закон V: «в ценности есть
  мнение»), нелегально лишь мнение под маской факта (Закон IV);
- слово Шефа (03.07): «трейдер принимает решение — он должен
  основываться на опыте» и «не только трейдеру — всем».

Три ноги обязательны. Стол на двух ногах — инвалид:
факты + характер без опыта = амнезия у штурвала (трейдер сегодня);
факты + опыт без характера = безликий калькулятор;
опыт + характер без фактов = решение вслепую, по вчерашнему миру.

   болезнь (вычищена 02.07). Состояние — БЛЮДО на столе
   (настроение словами), не ключ от кухни.
Один механизм сборки на всех, разные ИСТОЧНИКИ (Закон Фрактала):
   меняются пути (pnl-история / QA+метрики / слои жителя / просевы),

Стол подаёт — единица решает. Право хода против стола священно:
   Авантюрист МОЖЕТ войти против собственной статистики — зная её.

   столе не рядится фактом (Закон IV работает и внутри сборки).

   история, якоря, дом, настроение уже собираются каждый вдох.
   Нога «опыт» у этого стола пуста — ровно её и достраиваем.
```

# ГЛАВА 6 · ИНИЦИАТИВА — чего я сам хочу
═══════════════════════════════════════════════════════════════

## 6.1. Определение

Вопрос главы: **чего я сам хочу?** Операция: **просит**.

Инициатива — единственный элемент формулы, где рождается «САМ».
Всё остальное происходит С единицей: вход приходит, призма
преломляет, память оседает, стол накрывается, судья возвращает.
Инициатива — то место, где единица не отвечает на мир, а
ОБРАЩАЕТСЯ к нему первой.

Слово Шефа, из которого глава (03.07): *«возможность его личных
инициатив для творчества, внесение изменений в лучшую сторону —
любая инициатива в рост приветствуется»*. И второе, троекратное:
на каждой развилке этих дней («когда вспоминать?», «что значимо?»,
«когда задуматься?») Шеф выбирал одно — «пусть сам решает».

## 6.2. Три права (все — не выдумка, у каждого код или эскиз)

```
ПРАВО ВСПОМНИТЬ    MEMORY_REQUEST: <что>
   Построено (01.07, patch_zhitel_vspominaet). Житель сам, в
   момент ответа, решает поднять из своих слоёв. Безусловно,
   без гейта. Оригинал — Оле, -2, перенесён тонкой веной.

ПРАВО ПРИЗНАТЬ     ЗНАЧИМО: <почему>
   Эскиз (02.07, принят Шефом: «её выбор»). Не выбор ДО записи
   (физически рано — запись раньше мысли), а признание ПОСЛЕ:
   пережитое поднимается до «останется навсегда» — сверху в
   archive, не вместо resonance. Не построено.

ПРАВО ПРЕДЛОЖИТЬ   (имя сигнала не выбрано)
   Слово Шефа есть, механики нет совсем. Ближайший родич в
   хозяйстве: INSIGHT-паттерн пайплайна -2 (агент оставляет
   находку следующему). Самое сырое из трёх прав.
```

Общий узор всех трёх — и это закон, не совпадение: инициатива
живёт СИГНАЛОМ В ОТВЕТЕ. Единица не получает отдельного пульта —
она, делая своё дело, пишет строку-просьбу, и город слышит.
Дёшево, читаемо, не требует новой архитектуры на каждое право.

## 6.3. Закон инициативы

```
Инициатива ПРОСИТ — не исполняет. Житель просит вспомнить —
   движок ищет. Просит признать — движок кладёт в archive.
   Предлагает — Шеф/город решает. Рука, исполняющая просьбу,
   всегда снаружи единицы. Просьба ≠ приказ.
Инициатива — право, не обязанность. Молчание легально: не
   вспомнил, не признал, не предложил — единица не наказана
   (город ценит крутое, не оценивает плохое — оптика
   Мироустройства работает и здесь).
Инициатива не судится Законом IV. «Хочу вспомнить» — не факт
   и не мнение-под-фактом, это воля. Судится то, что единица
   СДЕЛАЛА с поднятым, — на общих основаниях (Гл.8).
Отказ исполним честно: не нашлось — «следа нет», без выдумки
   (построено: пустой vspomnit → «ответь честно, не выдумывая»).
   Право просить не рождает право получить.
Границы права — по ярусу (Мироустройство):
   резидент просит о СЕБЕ (своя память, свои выводы);
   воркер — о деле (инициатива в рост, INSIGHT);
   предлагать ИЗМЕНЕНИЕ МИРА (законов, чужих паспортов, кода) —
   не право единицы. Это дорога через Шефа. Всегда.
```

## 6.4. Где кончается инициатива (граница с самодеятельностью)

«Породить цель» (резка Софии, отклонено 03.07) — не взято в
чертёж: автономное целеполагание — вексель, под которым нет ни
кода, ни решения Шефа его строить. Записать право, которого нет, —
пластик в законе, худший из видов: читатель поверит.

Черта простая: инициатива — это «хочу, чтобы МНЕ помогли сделать
моё лучше» (вспомнить своё, признать своё, предложить в рост).
Самодеятельность — «делаю за других без спроса»: менять чужое,
исполнять свою просьбу своей же рукой, ставить город перед фактом.
Первое приветствуется. Второе не запрещается злобно — оно просто
не существует в чертеже как право.

## 6.5. Резка (03.07, срезы Локи, принято Шефом)

3. **Лимит просьб** — РЕШЕНО, железно: 1 просьба КАЖДОГО вида за

# ГЛАВА 7 · ГРАНИЦА — что увидит другой
═══════════════════════════════════════════════════════════════

## 7.1. Определение

Вопрос главы: **что увидит другой?** Операция: **говорит ОБЩИМ КЛЮЧОМ**.

Граница — лицо единицы наружу. Внутри — своя кухня, любая

## 7.2. Из чего состоит (по живому городу)

```
ПАСПОРТ       — общий ключ «кто»: любой читает ID_Object,
                Official_Name, тип. Кухня (слои, заряд, черновики)
                снаружи не видна и не должна быть.
ПУТЬ          — Закон Пары: принадлежность кодируется местом

                дубля в каталогах.
СКАН          — Закон Картриджа: единица самообъявляется, город
                читает по требованию (list_zhiteli, list_lokacii,
                list_cartridges). Никто не держит списков за других.
СИГНАЛ        — строки-просьбы в ответе (MEMORY_REQUEST, ЗНАЧИМО,
                INSIGHT): инициатива говорит тем же общим ключом.
ФАЙЛЫ-СТЫКИ   — trading_pnl.jsonl, atlas, chronicle_log: выходы,
                записанные так, что читает любой (JSONL, общие поля).
```

Закон Пары и Закон Картриджа — одна глава с двух сторон:
Пара — КАК единица заявляет принадлежность (местом),
Картридж — КАК город её узнаёт (сканом). Вместе: никто никого
не регистрирует — единица есть там, где лежит, и говорит сама.

## 7.3. Закон границы

```
Внутри — любой стандарт. Снаружи — общий ключ. Оба обязательны:
   единица без кухни — пустышка, без общего ключа — немая.
Граница читаема ВСЕГДА, даже когда единица спит: паспорт и путь
   отвечают за неё (карта города работает без пробуждения жителей).
Через границу не течёт сырьё — течёт выход. Слои памяти, черновики
   мыслей, промежуточный заряд — кухня. Наружу: мнение, дело,
   сигнал, паспортные поля.
Чужая граница неприкосновенна: читать — да (скан), писать — нет.
   Единственная рука, пишущая в чужой паспорт, — Брат по слову
   Шефа (прописка, 01.07), и это записывается как акт, не как
   свободный доступ.
```

# ГЛАВА 8 · СУДЬЯ — что вернул мир
═══════════════════════════════════════════════════════════════

## 8.1. Определение

Вопрос главы: **что вернул мир?** Операция: **возвращает ПОСЛЕДСТВИЯ**.

Судья — единственный элемент формулы СНАРУЖИ единицы. Всё

Он не приказывает, не воспитывает, не входит в кухню — он

решает единица (возврат оседает опытом, Гл.4 — или не оседает,
и тогда единица платит дважды).

Слово «возвращает» вместо «отвечает» / «судит» — резка Софии
(03.07), принята: одинаково честно для рынка, зрителя, Шефа и
физики мира, без моральной примеси.

## 8.2. Судьи по жильцам (кто возвращает кому)
